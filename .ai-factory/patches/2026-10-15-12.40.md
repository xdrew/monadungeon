# Lord Karak: reveal logged before the placement, untestable tie dice, missing player fields

**Date:** 2026-10-15 12:40
**Files:** src/src/Game/Field/Field.php, src/src/Game/GameLifecycle/Game.php, src/src/Api/Game/Get/Response.php, src/tests/Game/Field/LordKarakRoomCountTest.php, src/tests/Game/GameLifecycle/LordKarakGameTest.php
**Severity:** medium

## Problem

Found by `/aif-verify` driving five Cursed Rooms through the real API (setup-game → pick/place/move/end-turn in the php container):

1. The LORD_KARAK turn action was recorded before PLACE_TILE.
2. The tie-break dice were random in a scripted test game (`diceRolls` ignored).
3. `players[].lordKarak` / `lordKarakHeroes` never reached the GET response.

## Root Cause

1. `Field::placeTile` dispatched `LordKarakRoomDiscovered` right after `TilePlaced`, before its own `PerformTurnAction(PLACE_TILE)`; nested handlers run synchronously, so the Game recorded its action first.
2. `Game` rolled through `TestMode`, whose dice queue lives in one PHP process; scripted dice persist on the Field (`Field::getNextDiceRoll`), which is what `Battle` uses.
3. `Get/Response::formatGameLifecyclePlayers` copies player fields through an explicit whitelist.

## Solution

1. The room count and event moved after the PLACE_TILE record; the room-count test asserts the order.
2. `Game::onLordKarakRoomDiscovered` takes its dice from `GetField` → `getNextDiceRoll`; the unit test stubs `GetField`.
3. `lordKarak`, `lordKarakHeroes` added to the whitelist.

## Prevention

- Dispatch follow-up events after the aggregate has recorded its own turn action.
- Every new random roll goes through `Field::getNextDiceRoll`, never `TestMode` directly.
- A new player field in `Get/Action.php` also needs the `Get/Response.php` whitelist; check the real GET once.
