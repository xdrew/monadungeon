# Implementation Plan: Oracle Hero (Taia) — Farseeing & Fateweaver

Branch: feature/oracle-hero (created from feature/wizard-hero @ 10f4503; heroes are merged to main together)
Created: 2026-10-14

## Original Request
Oracle hero (Taia, Karak) — the last hero after the Wizard, same pattern as .ai-factory/plans/feature-wizard-hero.md. Rulebook (a4-karak-rulebook.pdf): "Farseeing. The Oracle has the best knowledge of all her enemies. If she fights in the first move of her turn, she gains a bonus of +1 to her roll. Fateweaver. The Oracle can influence her future. Anytime she is supposed to draw a token from the bag of monsters and treasures, she draws two tokens instead, choosing one to place on the tile and putting the other one back in the bag."

Follow-up answers: settings as for the Wizard (PHPUnit only, showcase untouched; logging standard; docs yes); Fateweaver is a real choice — the backend draws two tokens, keeps a pending choice, a new API action resolves it and the frontend shows a two-token dialog (an AI Oracle picks automatically); Farseeing "first move" = no move of the turn spent yet when the battle starts (`performedActionsCount === 0`; placing a tile does not spend a move, so the usual "open a room and fight" gets the +1).

## Settings
- Testing: yes (PHPUnit only; `fe/e2e/tests/two-player-game.spec.ts` is NOT changed — Player 1 stays Warrior, Player 2 stays Thief)
- Logging: standard (message-bus middleware logs the commands/events; no extra log statements)
- Docs: yes (rules.md Heroes section, README bullet)

## Requirements Reconciliation
Authority: rulebook text (above) > existing implementation (`Battle.php`, `Field.php`, `Bag.php`, `GameTurn.php`, `Movement.php`).

| Decision / supported combination | Source | Verification |
|---|---|---|
| Farseeing: `Battle::start` asks `GetTurn($turnId)` for `getPerformedActionsCount()`; the bonus applies when the hero `fightsBetterOnFirstMove()` and the count is 0. The flag is persisted in `battle.farseeing` (like `hp_sacrificed`) because the roll and the finalization are two commands. The +1 is added to `totalDamage` everywhere `sacrificeBonus()` is added and excluded from `itemDamage` in the same way, so `diceRollDamage + itemDamage + bonuses = totalDamage` still holds. A Warrior reroll or Swordsman ones-reroll does not change the flag. | rulebook; `GameTurn::updateActionCounter` (MOVE / USE_TELEPORT / MAGIC_SWAP count, PLACE_TILE / PICK_TILE / ROTATE_TILE do not) | `OracleFarseeingTest` (a)–(d), `GameTurnTest` |
| `BattleCompleted::$farseeing` → `lastBattleInfo.farseeing`; FIGHT_MONSTER `additionalData['farseeing']` and `heroAbility` part `farseeing`. | FE needs to show the +1 | (a), (d) |
| Fateweaver only triggers in `Field::placeItem` (the single place a token is drawn), for a room tile, when the current player's hero `drawsTwoTokens()` and the bag holds ≥ 2 items; with 1 item left it is a normal draw. The two `Item`s are stored in `Field::$pendingFateweaver = {fieldPlace, items}` (new jsonb column, migration), the tile gets no item yet. | rulebook "anytime she is supposed to draw" | `OracleFateweaverTest` (a), (f) |
| Resolution = new command `ChooseFateweaverItem(gameId, playerId, turnId, itemId)` handled by `Field`: current player + pending exists + `itemId` is one of the two, else `\DomainException`; chosen → `$this->items[fieldPlace]`, other → `Bag::returnItem()`; turn action `TurnAction::FATEWEAVER` (does not count as a move; allowed only right after PLACE_TILE; anything is allowed after it). | keep rules in the domain | (b), (c) |
| An AI Oracle never waits: `placeItem` resolves immediately with `Field::pickFateweaverToken()` — a token without a guard (chest / treasure) wins, otherwise the lowest `guardHP`. No FATEWEAVER turn action for the AI: `placeItem` runs on `TilePlaced`, which is dispatched before the PLACE_TILE action is recorded, so the action rule "only after PLACE_TILE" would reject it. | AI must not stall (`SmartVirtualPlayer` does not know hero abilities) | (e) |
| While a choice is pending: `getAvailablePlacesForPlayer` returns empty `moveTo` / `placeTile`; `Movement::movePlayer` throws `InvalidMovementException('Choose the Fateweaver token first')`. If the turn ends anyway (`TurnEnded`), `Field::onTurnEnded` resolves it with the first drawn token (no turn action, the turn is over). | no stuck games, no walking onto an item-less room | (a), (g), (h) |
| `Bag::returnItem(Item)`: inserted at a random position (`random_int`), appended at the end when `TestMode` is enabled so fixed item sequences stay predictable; `Bag::count()` for the ≥ 2 check. | "putting the other one back in the bag" | `BagTest` |
| API: `POST /game/fateweaver` (new action, same shape as `/game/magic-swap`); `PlaceTile` response gains `fateweaverChoice` so the click flow can prompt before moving; `GET /game/{id}` state gains `fateweaverChoice` so a reloaded page can still resolve it. | FE shows what the backend returns | manual check in Task 7 |
| Backend owns the rules; frontend reads `battleInfo.farseeing`, `heroFlags.drawsTwoTokens`, `state.fateweaverChoice`, the place-tile response and the turn-log `fateweaver` action. | keep rules in the domain | modal, GameView, ActionLog |
