# Implementation Plan: Base-theme art generation with Gemini (style bible + manifest-driven script)

Branch: feature/art-generation (created from feature/base-theme @ 87c47bf; the Karak branches are merged to main together)
Created: 2026-10-14

## Original Request
Генерация артов базовой темы через Gemini (ключ есть, хранить в .env как GEMINI_API_KEY): персистентная стайл-библия в репо (промпт стиля, палитра, референсы из текущих артов — пиксельные иконки предметов key/axe/sword/dagger/chest, тайлы, lobby-bg), чтобы арт был согласованным по стилю и сеттингу между запусками; скрипт генерации по манифесту ассетов: 8 монстров и 7 героев базовой темы в стиле текущих пиксельных иконок предметов на прозрачном фоне (fe/public/themes/base/monsters|heroes/<key>.webp), плюс арт главного экрана (фон лобби в стиле текущего lobby-bg, но с монстрами Karak) для базовой темы; каждая генерация получает референсы на вход; лог/манифест сгенерированного для повторяемости.

Follow-up answers: workflow `/aif-plan full → /aif-implement`; sprites in the style of the current item icons (key/axe/sword/dagger/chest), not painterly; the current art is the style reference; no tests, logging standard, docs yes; Python on the host (`tools/art/`, google-genai + Pillow); one variant per asset written straight into `fe/public/themes/base/`, re-generate by name with `--only <id> --force`.

## Settings
- Testing: no (tool script; verified by running it and by looking at the result in the base theme; `fe/e2e/tests/two-player-game.spec.ts` is NOT changed)
- Logging: standard (Python `logging`, INFO per asset: model, number of references, duration, output path; WARN for green residue / fallbacks / retries; `--verbose` switches to DEBUG and prints the full prompt and reference list; the generation log file is the persistent record)
- Docs: yes (`tools/art/README.md`, root `README.md` "Art generation" section, `fe/public/themes/base/README.md` points to the tool)

## Requirements Reconciliation
Authority: user request + follow-up answers (above) > official Gemini API docs (https://ai.google.dev/gemini-api/docs/image-generation, read 2026-10-14) > community practice for transparency (https://www.philschmid.de/generate-stickers) > current repository art (`fe/public/images/*.webp`, `fe/public/assets/tiles/*.webp`, `fe/public/themes/monad/lobby-bg.webp`).

| Decision / supported combination | Source | Verification |
|---|---|---|
| The API: `google-genai` 2.x Python SDK, **Interactions API** `client.interactions.create(model, input=[{type:"image", data:<base64>, mime_type}, …, {type:"text", text}], response_format={"type":"image","aspect_ratio":…,"image_size":…})`; the image comes back base64 in `interaction.output_image.data` (docs) or as the last `type == "image"` entry of `interaction.outputs` (tutorial) — the client wrapper handles both shapes. Default model **`gemini-nano-banana-2.1`** (the docs' recommended workhorse, up to 14 reference images, up to 5 "character" references); `--model gemini-3-pro-image` is the premium option used by default for the lobby background. `gemini-2.5-flash-image` is legacy and not used. | official docs | `python -m tools.art probe` generates one 1:1 image with one reference and prints the response shape and model |
| The API key lives in **`tools/art/.env`** (`GEMINI_API_KEY=…`, gitignored by `tools/art/.gitignore`) or in the process environment; the root `.env` is **tracked by git** and must never receive the key. The tool refuses to run without a key and never logs it. | request "хранить в .env"; `git ls-files .env` shows the root file is tracked | `git check-ignore tools/art/.env` → ignored; `git status` after a run shows no `.env` |
| Transparency: Gemini models do not return a usable alpha channel, so sprites are generated on a flat chroma-key green `#00FF00` with a thin white outline (the prompt forbids green on the subject) and the tool removes the green in post (HSV mask: hue 120±25°, S>75%, V>70%, 2 px dilation, alpha snapped to 0/255), crops to the content bbox, pads 6 % and resizes to the target size (LANCZOS). Output = RGBA webp (lossless) like the existing sprites. | community practice; existing sprites are 100×100 RGBA webp (`key.webp`), figures 100×150 (`player.webp`) | post-processed PNG shows real alpha (`PIL mode RGBA`, corner pixels alpha 0), green residue < 0.5 % of opaque pixels else WARN |
| Asset sizes: monsters 100×100 (like `themes/monad/monsters/*.webp`, shown at 32–80 px), heroes 100×150 full-body figures (like `player.webp`, shown at 26–45 px and as the 40×40 `hero-portrait` cover), lobby background 1536×1024 RGB webp quality 85 (like `themes/monad/lobby-bg.webp`). Generation at `image_size: "1K"`, aspect 1:1 for monsters, 2:3 for heroes, 3:2 for the background. | existing files | `python -c "from PIL import Image; …"` prints the sizes/modes of every output |
| Style bible (persistent, committed): `tools/art/style/STYLE.md` (human notes: setting, palette, do/don't) and `tools/art/style/style.json` (machine: `style_prompt`, `negative_prompt`, `palette` hex list, `sprite` and `background` prompt frames, `references` = paths under `fe/public` with a role: `style` for item icons/figures/tiles, `composition` for `lobby-bg.webp`). Every call sends the style references first, then the subject prompt built from the frame + the asset's `subject`. | request "персистентная стайл-библия" | `--dry-run` prints the final prompt and the ordered reference list per asset |
| Consistency across runs: assets are generated in the manifest order; after each sprite is accepted its **processed** file is appended to a rolling list of "character" references (the 5 most recent) for the following sprites of the same kind, so later monsters match earlier ones; the lobby background receives up to 5 generated monsters (dragon, skeleton_king, mummy, giant_spider, giant_rat) as character references plus `lobby-bg.webp` and a tile as style/composition references. Reference order and roles are recorded per asset in the log. | request "каждая генерация получает референсы на вход"; docs: ≤14 refs, ≤5 character refs | log entries list the references used |
| Manifest `tools/art/assets.json`: 16 entries `{ id, kind: "monster"|"hero"|"background", out, subject, extra_refs? }` with `out` pointing to the exact paths the base theme expects (`fe/src/theme/base.js`): `fe/public/themes/base/monsters/{giant_rat,giant_spider,mummy,skeleton_turnkey,skeleton_warrior,skeleton_king,fallen,dragon}.webp`, `fe/public/themes/base/heroes/{adventurer,warrior,thief,swordsman,warlock,wizard,oracle}.webp`, `fe/public/themes/base/lobby-bg.webp` (+ `lobbyBackground` in `base.js`). | theme contract from feature/base-theme | after a full run `ThemedImage` shows no emoji fallback and the lobby has the background |
| Generation log `tools/art/generated.json` (committed): per asset `{ id, model, prompt_sha256, references: [{path, role}], raw: "out/raw/<id>.png", output, generated_at, duration_s, post: {green_residue_pct, bbox} }`. Raw API images go to `tools/art/out/` (gitignored). `--force` regenerates an asset that already has an output; without it existing outputs are skipped; `--only a,b` restricts the run; `--dry-run` builds prompts without calling the API. | request "лог/манифест сгенерированного для повторяемости" | run twice: second run skips everything; `--only dragon --force` regenerates one |

Monster prompts follow the Karak tokens (giant rat, giant spider, mummy, skeleton with a key ring = turnkey, skeleton warrior with sword, skeleton king with crown, the Fallen = spectral knight, dragon). | `HeroType::label()`, `ItemName` | subjects in `assets.json` |

## Tasks

### Phase 1: Tool skeleton, style bible, client
- [x] Task 1: `tools/art` package skeleton and configuration
  - `tools/art/requirements.txt` (`google-genai>=2.30`, `pillow>=10`, `numpy>=1.26`); `tools/art/README.md` (setup: `python3 -m venv tools/art/.venv && tools/art/.venv/bin/pip install -r tools/art/requirements.txt`, key in `tools/art/.env`, commands); `tools/art/.gitignore` (`.venv/`, `.env`, `out/`); `tools/art/.env.example` (`GEMINI_API_KEY=`).
  - `tools/art/__init__.py`, `tools/art/__main__.py` (argparse: subcommands `probe`, `generate`, `list`; common flags `--model`, `--verbose`, `--dry-run`, `--only`, `--force`); `tools/art/config.py`: `load_api_key()` reads `GEMINI_API_KEY` from the environment, else parses `tools/art/.env` (no python-dotenv; simple `KEY=value` lines), raises `SystemExit('GEMINI_API_KEY is not set…')` otherwise; `ROOT = Path(__file__).resolve().parents[2]` so all paths in the manifest are repo-relative.
  - Logging: `logging.basicConfig(level=INFO, format='%(asctime)s %(levelname)s %(message)s')`, `--verbose` → DEBUG. Never log the key.
  - Files: tools/art/{requirements.txt, README.md, .gitignore, .env.example, __init__.py, __main__.py, config.py} (new). Note: root has no `.gitignore`, so the tool-level one is the guard for `.env` and `out/`.
- [x] Task 2: Style bible and asset manifest (depends on 1)
  - `tools/art/style/style.json`: `style_prompt` ("small game sprite icon in the style of the attached reference icons: clean cartoon pixel-art look with crisp edges, soft painterly shading, warm torch-light highlights, dark fantasy dungeon palette (aged gold, worn leather brown, bone white, mossy green, stone grey, ember orange), slight dark outline, 3/4 front view, single subject, centered with padding"), `negative_prompt` ("no text, no watermark, no frame, no background scene, no green on the subject, no blur, no photo-realism"), `palette` (8–10 hex values picked from `key.webp`, `axe.webp`, `chest-closed.webp`, `player.webp`), `sprite_frame` with the chroma-key clause ("background EXACTLY flat #00FF00 (RGB 0,255,0), no gradient or shadow on it; clean white 2–3 px outline around the subject"), `background_frame` for the lobby art ("wide painterly dark stone dungeon hall lit by wall torches, an open wooden treasure chest full of gold coins at the centre, the attached monsters gathered around it in the same composition as the attached reference painting, moody, deep shadows, warm orange light, no text"), `references`: `[{path:"fe/public/images/key.webp", role:"style"}, axe, sword, dagger, chest-closed, player (role style, for heroes), ai, {path:"fe/public/assets/tiles/c-1111.webp", role:"style"}, {path:"fe/public/themes/monad/lobby-bg.webp", role:"composition"}]`, `limits: { max_references: 14, max_character_references: 5 }`.
  - `tools/art/style/STYLE.md`: one page — setting (Karak dungeon), what the existing icons look like, palette swatches, sprite rules (silhouette readable at 32 px, no scene, no text), hero/monster identity notes, how to extend (add a reference, bump `style_version`).
  - `tools/art/assets.json`: the 16 entries from the table (ids = theme keys, `kind`, `out`, `subject`), plus `size` defaults per kind in `style.json` (`monster: {w:100,h:100,aspect:"1:1"}`, `hero: {w:100,h:150,aspect:"2:3"}`, `background: {w:1536,h:1024,aspect:"3:2", model:"gemini-3-pro-image", quality:85}`); the background entry lists `character_refs: ["dragon","skeleton_king","mummy","giant_spider","giant_rat"]`.
  - `tools/art/manifest.py`: dataclasses `Asset`, `Style`, loaders with validation (unknown kind, missing reference file, duplicate id → `SystemExit` with the offending entry).
  - Files: tools/art/style/{style.json, STYLE.md}, tools/art/assets.json, tools/art/manifest.py (new).
- [x] Task 3: Gemini client wrapper and `probe` (depends on 1)
  - `tools/art/gemini.py`: `class ImageClient(model, api_key)`; `generate(prompt: str, references: list[Path], aspect_ratio: str, image_size: str = "1K") -> bytes` builds `input` = image blocks (base64 + mime from the file, webp → the SDK accepts `image/webp`; if the probe shows it does not, convert references to PNG in memory with Pillow) followed by the text block, calls `client.interactions.create(...)` with `response_format={"type":"image","aspect_ratio":aspect_ratio,"image_size":image_size}`; extracts the image from `interaction.output_image.data` or the last `outputs[*].type == "image"` entry; raises `GenerationError` with the response summary when no image is returned; retries 3× with exponential backoff on 429/5xx (`google.genai.errors.APIError` status codes). DEBUG logs: model, aspect, number of references, prompt length; INFO: `generated <id> model=… refs=N in 12.3s`.
  - `probe` subcommand: one call with `key.webp` as reference and the style prompt + "a small iron padlock", aspect 1:1, writes `tools/art/out/probe.png` and logs the response type / attribute names so the SDK contract is confirmed before the batch.
  - Files: tools/art/gemini.py (new), __main__.py (probe wiring).

### Phase 2: Post-processing and pipeline
- [x] Task 4: Sprite and background post-processing (depends on 2)
  - `tools/art/postprocess.py`: `remove_chroma_key(img: Image) -> Image` (RGB→HSV via numpy, mask hue 120±25°, S>0.75, V>0.70, dilate 2 px with `PIL.ImageFilter.MaxFilter(5)` on the mask, alpha=0 under the mask, then snap alpha <64→0 else 255), `trim_and_fit(img, w, h, padding=0.06)` (bbox of alpha, square/rect pad to the target aspect, LANCZOS resize), `green_residue_pct(img)` (opaque pixels still green-dominant), `save_sprite(img, out: Path)` → `webp` lossless RGBA; `fit_background(img, w, h)` (cover-crop + resize) and `save_background(img, out, quality=85)` → RGB webp. WARN when residue > 0.5 % or the bbox touches the border (subject cropped by the model).
  - Files: tools/art/postprocess.py (new).
- [x] Task 5: `generate` pipeline, log, run it (depends on 3, 4)
  - `tools/art/pipeline.py`: `run(assets, style, only, force, dry_run, model_override)`: for each asset in manifest order → skip when `out` exists and not `force` (INFO "skip <id>: exists"); build prompt = `style_prompt` + frame + `subject` + `negative_prompt`; references = style refs for the kind (sprites: icons + figures + tile; background: lobby-bg composition + tile) + rolling character refs (last 5 processed sprites of the same kind; for the background the `character_refs` outputs that exist), capped at 14; `--dry-run` logs prompt + refs and continues; else call the client, save raw PNG to `tools/art/out/raw/<id>.png`, post-process by kind, write `out`, append the asset to the rolling refs, and upsert `tools/art/generated.json` (schema from the table; `prompt_sha256` over the final prompt text).
  - `fe/src/theme/base.js`: `lobbyBackground: '/themes/base/lobby-bg.webp'`; `fe/public/themes/base/README.md`: point to `tools/art` and list `lobby-bg.webp`.
  - Run: `probe` first, then `generate` for the 15 sprites, inspect them in the base theme (lobby hero picker, rules page monsters, a game tile with a monster), regenerate the unconvincing ones with `--only <ids> --force`, then `generate --only lobby_bg` with `gemini-3-pro-image`. The user does the visual acceptance; the plan's token accounting records the number of API calls.
  - Files: tools/art/pipeline.py (new), __main__.py (generate/list wiring), fe/src/theme/base.js, fe/public/themes/base/README.md, generated assets under fe/public/themes/base/, tools/art/generated.json.
