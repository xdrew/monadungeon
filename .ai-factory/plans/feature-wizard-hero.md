# Implementation Plan: Wizard Hero (Argentus) — Magical Affinity & Astral Walking

Branch: feature/wizard-hero (created from feature/warlock-hero @ 58d90d5; heroes are merged to main together)
Created: 2026-10-14

## Original Request
Wizard hero (Karak) — the next hero after Swordsman and Warlock, same pattern as .ai-factory/plans/feature-warlock-hero.md

Follow-up answers: settings as for the Warlock (PHPUnit only, showcase untouched; logging standard; docs yes); Astral Walking has no separate UI mode — the backend simply adds the tiles behind walls to `availablePlaces.moveTo`; Magical Affinity keeps only the fireball ("magic bolt"), the teleport scroll ("portal of healing") is consumed as usual; there is no curse in this game, the curse clause is ignored.

Rulebook text (a4-karak-rulebook.pdf, "Argentus, the Wizard"):
> Magical Affinity. The Wizard knows how to use the magic bolts more effectively, and for this reason his scrolls are not consumed when used. However, this does not apply to the portal of healing and if the Wizard is cursed, he has to discard the magic bolt spells during combat just like the others.
> Astral Walking. The Wizard can move through walls, thus he does not have to respect the continuity of the dungeon. This, however, can be used only while moving over the discovered tiles.

The kept ids travel in `BattleFinalized::$keptConsumableIds` so `Field::onBattleFinalized` marks only the really consumed ids in `consumedItemIds` (otherwise a later drop of that same fireball would silently vanish instead of landing on the field). | rulebook; `Field::onBattleFinalized`, `Field::onItemRemovedFromInventory` | (a), (b), (d) |
| `BattleCompleted::$spellsKept` (true when ≥1 fireball was used and kept) → `lastBattleInfo.spellsKept`; FIGHT_MONSTER `additionalData['spellsKept']` and `heroAbility` part `magical_affinity`. A battle with no selected spells reports `spellsKept = false` and no ability. No DB migration: the flag is a transient private property set and consumed inside the same `finalizeBattle` command. | FE needs to say "spell kept" instead of "used" | (a), (c) |
| Inventory-full flow: for the Wizard a used fireball does not free a spell slot, so when the reward is a spell and the spell slots are full he must replace an item like anyone else. Backend already behaves so (nothing removed); the frontend's "consumed spells free a slot" shortcut is skipped for `heroFlags.keepsSpellsInCombat`. | code `GameView.handleFinalizeBattle` | manual check in Task 6 |
| Astral Walking is an extra transition rule in `Movement::movePlayer`: when the normal `canTransition` is false, a hero with `walksThroughWalls()` may still move to an **orthogonally adjacent** position that **already has a placed tile** (`MovementService::canWalkThroughWallTo`). Everything else is a normal MOVE: costs 1 move, stunned rule, "cannot move after battle", a monster on the target tile starts a battle, a reward on it defers the turn end. Diagonals never qualify; an empty (undiscovered) neighbour never qualifies — new tiles are still placed only through a door (`placeTile` list untouched). | "only while moving over the discovered tiles" | `AstralWalkingTest` (a)–(e) |
| A through-wall MOVE is recorded with `additionalData['throughWall'] = true` and `heroAbility = 'astral_walking'`; a move through a real door by the Wizard records nothing special. | action log | (a), (b) |
| `Field::getAvailablePlacesForPlayer` adds the adjacent placed tiles (no door needed) to `moveTo` for a `walksThroughWalls()` hero so the frontend markers and the AI (`SmartVirtualPlayer` reads this query) see them; `placeTile` is still derived from the door transitions only. The deck-empty filter in `Api/Game/Get/Response.php` keeps placed tiles, so it stays compatible. | keep rules in the domain; FE shows what the backend returns | `FieldTest` new case |
| Backend owns the rules; frontend reads `battleInfo.spellsKept`, `heroFlags.keepsSpellsInCombat`, `availablePlaces.moveTo`, and the turn-log `throughWall` flag. | keep rules in the domain | modal, GameView, ActionLog |
